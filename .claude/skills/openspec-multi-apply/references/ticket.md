# 工单格式

用于编排者拟定前沿工单，交文书员通过文书任务落盘。创建时机、编号和内容完整性规则见 SKILL.md「一·五、写工单文件」。修复轮不写工单文件，原工单即依据；通用规则见 [checklist.md](checklist.md)。

```markdown
# T<编号>：<简短标题>

- openspec：<change 名> / 任务 <如 2.1>
- 被谁阻塞：<已完成的 T 编号，或「无」>

## 目标
<一句话：完成后用户/调用方能观察到什么行为。>

## 动手前先读
- <项目规矩、相关 spec requirement/scenario、design 决定、要改的文件>
- <前置工单已产出、这张单要用到的东西（接口名、文件）>
- <有探路摘要时：`_tickets/_receipts/S<编号>-scout.md`>
- <风险单：`_tickets/_receipts/T<编号>-design.md`（设计要点）>

## 边界
- 只动：<文件 / 模块>
- 风险：<命中的风险信号；都不命中写「无」>
- 适用通用规则：<路径 / 密钥 / 并发 / SQL 中涉及的几类；都不涉及写「无」>
- 必须保持：<design 里不能动摇的决定、要兼容的已有行为；引用章节里与本单相关的硬规则逐条列出并标出处，如「03 §7.1：每个 retriever 对同一 chunk 最多贡献一次」>

## 验收
1. `<命令>` → <预期结果>

## 为什么这样验收
<这些检查要保住的真实目的，引用 spec scenario；说明怎么确认测试不是空断言。>
```
