# 探路者派单数据

固定职责、模型、effort 和工具白名单在 `.claude/agents/openspec-scout.md`，这里不重复。派单时 `subagent_type: "openspec-scout"`，description 写「探路 S<编号>」，prompt 只写本次数据：

```text
仓库根目录：<路径>
change/工单/上下文路径：<路径列表>
探索范围：<模块或文件>
观察基准：<提交，及需考虑的未提交文件>
具体问题：
1. <能用证据回答的问题>
2. <如有>
```

- 问题要具体、能用证据回答；一份短摘要说不清的，按模块或问题拆成几次探路，影响拆单的出处和未决项都要保留。
- 拆单前还没有工单时直接给文件路径和问题，不为探路先建一张施工工单。
- 互不依赖的问题同一条消息里并行派，依赖前一份结果的顺序派。

## 设计探路（风险单）

description 写「探路 设计 T<编号>」，「具体问题」固定为下面几条（不适用的写「无」）：

1. 本单要守住的不变量（状态流转、终止事件、锁、幂等、确定性），各给出处。
2. 要接的真实契约：调用点（文件:行号）、错误和数据的真实形态。
3. 方案取舍：可选做法不超过 2 个，推荐哪个、为什么。
4. 质量标准（内容类工单）：合格和不合格的样例各一条。
5. 已知坑：LESSONS.md 或同族工单踩过的。

回传仍不超过 15 行，编排者据此拟 `_tickets/_receipts/T<编号>-design.md` 交文书员落盘。
