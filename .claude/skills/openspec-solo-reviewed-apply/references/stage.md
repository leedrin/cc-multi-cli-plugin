# 阶段审查与终审报告格式（审查员写）

每个 `## N` 任务组（PLAN.md 里「阶段」列相同的单）全部收尾后审一次：`_solo-rv/_review/STAGE-<阶段号>.md`；全部完成后再审一次：`_solo-rv/_review/FINAL.md`。审的是**单与单之间**的问题，单张工单内部的已经审过了。完成前第一行写 `进行中 @<时间>`。

```
# 阶段审查 <阶段号>｜<日期时间>

- 类型：<阶段审 / 终审>
- 阶段：<阶段号，终审写「全部」>
- 工单：<本阶段全部完成的 T 编号，终审列全部完成的单>

## 跨单检查
1. 接口一致｜<前一张单产出的类型/函数签名，与后一张单的调用是否一致；实际核对了哪几处>｜<结果>
2. 重复实现｜<不同单是否各写了一份同一逻辑；grep 了什么>｜<结果>
3. 死代码｜<桩、未被引用的导出、被后续单取代的旧代码；查了什么>｜<结果>
4. 场景覆盖｜<本阶段任务对应的 SCENARIOS.md 场景是否全部有测试；怎么核对的>｜<结果>
5. 共享状态｜<各单测试是否共用同一个文件/端口/全局状态、顺序依赖；怎么查>｜<结果>
<终审再加：6. 任务覆盖｜<tasks.md 每条任务能否对应到场景或提交>｜<结果>>

## 探针
1. <亲手执行的命令（如把本阶段所有单的测试文件一起跑、grep 重复定义）> → <结果> → <说明>

## 发现
<N. 严重程度｜归属｜类型｜文件:行号｜问题｜代码证据｜怎么改；或 无发现（查了什么：…）>

## 结论
结论：<通过 / 开修复单 / 阻塞>，<一句话理由>
```

## 写法要求

- 模板以 `node <技能目录>/scripts/records.mjs skeleton stage` 的输出为准；写完跑 `records stage <报告>` 到 `OK`。
- 五个检查项（终审六个）一个不能少，每项都要写出实际核对的位置和结果，不能只写「无问题」。
- 「无发现」至少 3 条探针（含把本阶段所有单的测试合并跑一次）。
- 有「高/中｜本单」发现，结论必须是「开修复单」：主 agent 会新建一张编号顺延的修复单，走完整的执行、审查、验收流程。
