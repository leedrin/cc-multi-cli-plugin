# 通用规则清单

执行和审查涉及下列领域的代码时逐条对照；工单「边界」里的「适用通用规则」指明本单涉及哪几类。条目来自以往审查中反复出现的高/中发现。项目特有的坑记在 `_solo/LESSONS.md`。

## 路径与文件系统
- 写、删、改名前，对实际目标路径及其每一级父目录检查符号链接 / junction / reparse point；用 realpath 确认仍在允许的根目录内（Windows 注意跨盘符）。
- 临时文件用随机名 + 独占创建（`wx` / `O_EXCL`），不打开固定名的 `.tmp`。
- 校验与使用之间不能让目标被替换：打开后对句柄校验，或在同一持锁区间内完成；句柄与路径的 dev/ino 相同不代表仍在根内。
- 递归删除只作用于自己创建并已校验的目录；调用方传入的路径先校验类型和范围。

## 密钥与出站内容
- Provider 请求、日志、stderr、索引、manifest、错误信息等所有出站内容，一律走项目统一的脱敏函数，不另写正则；统一函数漏了就补在统一函数里。
- 测试至少覆盖：带引号的 JSON 键、单/双引号值、`=` `:` `=>` 赋值、`Bearer <token>`、同一行多个密钥、URL 内凭据。
- 脱敏后的内容若还参与 hash、比较或定位，确认两边口径一致。
- 过滤后无法满足必需内容的，按 spec 拒发，不静默继续。

## 并发与状态
- 「检查是否忙 / 是否存在」和随后的动作放在同一把锁里。
- 锁、租约的所有权比较完整身份（持有者 + 获取时间或令牌），不只比 id。
- 失败、取消路径不留半成品，或留下的能被下一次运行安全识别和清理。

## SQL 与 schema
- 比较 schema 时不改写字符串字面量（不去空白、不忽略大小写）；未知的表、索引、trigger 要拒绝，不按名称前缀放过。
- 迁移前先校验版本与兼容性；拒绝打开时库不能已被修改。

## 测试
- 回归测试在修复前必须失败；断言落到实际行为（调用次数、写入路径、文件内容），不只看返回值。
- 边界测试同时覆盖恰好在上限内和超出一个单位两侧。
